## Tasks
A task owns the requested outcome, numbered requirements, repository, workflow, and accountable person. Clarify assumptions before a run writes code.

## Runs
A run is one execution attempt. It records workspace identity, role steps, tool decisions, validation, review findings, budgets, and delivery status.

## Retry without erasing history
Start a new run after a failed or rejected attempt. Preserve the prior run so reviewers can compare what changed and why the next attempt exists.
